# M-1000 Maxigun ← E/MG-101 HMG Emplacement — 射弹替换 + 开火可移动

给《绝地潜兵 2》用的 Lua 注入式 mod，跑在 [Bingus Shared Loader](https://github.com/CowboyBingus/HD2-BingusSharedLoader) 上。

**把背包加特林的子弹，换成重机枪部署支架的子弹；并解锁开火时移动。**

---

## ⚠️ 两件事先说

### 1. 这个版本没有在游戏里实测过

代码结构完整、逻辑按**已验证的数据**写，**但「实际生效」这一步没做**。

**装之前请先用日志确认**：

```
%LOCALAPPDATA%\CowboyBingus\Helldivers2\Logs\MaxigunHMGRound-STATUS.txt
```

成功应看到：

```
projectile swap : true
fire while move : true
```

> 如果你跑通了，欢迎反馈 —— 这是目前最缺的一环。

### 2. 反作弊风险

- 运行时修改游戏内存，**可能违反游戏 ToS**
- **仅客户端生效**，队友看不到
- 建议**单人 / 知情固定队**使用
- 退出游戏**完全还原**，不写磁盘
- 版本不符**拒绝运行**（校验 `game.dll` SHA-256）

## 二、改了以后差多少

| 参数 | 改前（Maxigun） | 改后（E/MG-101） |
|---|---|---|
| **伤害 / 耐久** | 80 / 18 | **200 / 40** |
| **穿甲** | AP3（中） | **AP4（重）** |
| **质量** | 11 g | **52 g** |
| **初速** | 920 m/s | **880 m/s** |
| 拆迁 / 硬直 / 推力 | 10 / 15 / 12 | 20 / 25 / 15 |
| **开火时移动** | ❌ 锁定 | **✅ 解锁** |

**两者属于完全不同的射弹族**（8×60mm vs 12.5×100mm），所以这是**跨族复制**：

- 伤害 **2.5×**
- 穿甲提升一级
- **质量增加 4.7×** → 弹道下坠和命中反馈会明显不同

## 三、改动一：换射弹

### 定位方法：按**伤害档案链接**，不靠索引

```
加特林的伤害档案 = 127  （从 *(game.dll + 58483896) 读到）
射弹行 +84 存着它用的伤害档案编号
全表 350 行里：

    dmgid 127  ->  唯一一条：索引 225
```

**为什么不能用索引**：全表有 **4 条速度都是 920**（索引 224/225/233/234），
**光看数值分不出来**。但**伤害档案链接是唯一的**。

### 改了什么

索引 225 那行改成与 E/MG-101 支架行**逐字节相同**（共 14 处）：

| 偏移 | 含义 | 加特林 → 支架 |
|---|---|---|
| +48 | 口径 | 8.0 → **12.5** |
| +56 | 弹速 | 920 → **880** |
| +60 | 弹重 | 11 → **52** |
| +84 | 伤害链接 | 127 → **204** |
| 其余 10 处 | 穿甲 / 标识 / 哈希 | — |

### 伤害是「顺带」一起变的

射弹行 `+84` 存的是**它用哪个伤害档案**：

```
加特林那行     +84 = 127
E/MG-101 那行  +84 = 204
```

v3 把**整行 272 字节**照抄过去，所以 `+84` 从 127 变成 204 ——
**射弹自动改用 HMG 的伤害档案**（200/40/AP4）。

**所以不需要单独的「只改伤害」版本** —— 换射弹时伤害已经跟着变了。

### 辅助定位

武器组件按 **1232 字节内容**搜索（嵌入参考 mod 公开的完整模板）。
组件表通过 `*(owner + (-13614272))` 到达，`owner = *(game.dll + 54973760)`。

> ⚠️ 组件表**装载很晚**，mod 会重试最多约 2 分钟。

### 兜底

如果按伤害链接找不到，会退回**整行 272 字节完全匹配**。
两者都不成立就**拒绝写入**。

## 四、改动二：开火时可移动

**照抄参考 mod，就一个字节：**

```lua
Minigun.WeaponDataComponent
  edits = {{ offset = 387, replacement = unhex("00") }}   -- 01 -> 00
```

包含它的 4 字节 dword：

```
+384 原值 = 0x01010001
+384 改后 = 0x00010001
```

**只有第 387 字节变化**（已逐字节验证）。

## 五、走过来的路（为什么这么多轮）

| 尝试 | 结果 |
|---|---|
| 改索引 224 | ❌ 写对了字节，但**游戏读的是 225** |
| 字节扫描找记录 | ❌ 记录是**指针解引用**到的，扫不到 |
| 按指纹识别 | ❌ 指纹太松，匹配到多行 |
| **按伤害链接识别** | ✅ **可行** —— `+84 == 127` 全表唯一 |
| 猜射弹类型字段 | ❌ `ProjectileWeaponComponent.ProjType` **始终没找到** |

**关键转折**：不再猜「加特林指向哪条射弹」，改成**从伤害档案反查**。

## 七、安全设计

- `game.dll` **SHA-256** 校验，版本不符**拒绝运行**
- 目标**必须先与捕获的字节完全一致**才写
- **写入后立即回读验证**
- 临时改页保护后**立即恢复**
- 伤害链接匹配到多行 → **不写**
- 武器记录**不用固定索引**（按内容搜）

1. **彻底退出游戏**

## 十、踩过的坑

| 坑 | 教训 |
|---|---|
| 改索引 **224** | 游戏读的是 **225** —— 有 4 条速度相同的行 |
| **字节扫描**找记录 | 记录是**指针到达**的，扫描找不到 |
| **指纹匹配** | 太松，多行都匹配 → 歧义 |
| **猜枚举编号** | 枚举**按构建版本变化**，社区 JSON 是旧快照 |
| `ProjectileWeaponComponent.ProjType` | **始终没定位到**，最后绕开 |
| 手写 hex 字面量 | 反复掉字节，**必须脚本生成** |
